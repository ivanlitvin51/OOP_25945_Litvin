--------------------------------------------------------------------------------
2.1. ЧТО ТАКОЕ ИНВАРИАНТ КЛАССА (CLASS INVARIANT)
--------------------------------------------------------------------------------
Инвариант класса — это совокупность условий и правил, которые ДОЛЖНЫ выполняться
для любого экземпляра класса на протяжении всей его жизни (после завершения
любого конструктора и до начала работы деструктора).

В классе Groupmate инвариант включает в себя следующие правила:
  1. Имя и фамилия (firstName, lastName) должны начинаться с заглавной буквы,
     а все последующие буквы должны быть строчными (например, "иван" -> "Ivan",
     "ПЕТРОВ" -> "Petrov").
  2. Возраст (age) студента должен быть в реалистичном диапазоне: от 16 до 100 лет.
     Если передано число < 16, оно принудительно корректируется до 16.
     Если передано число > 100, оно корректируется до 100.
  3. Оценки (marks) должны соответствовать академической шкале: от 2 до 5.
     Любая оценка ниже 2 становится 2, любая оценка выше 5 становится 5.
  4. Размер массива marksCount неотрицателен, а указатель marks указывает на
     валидный непрерывный блок из marksCount элементов типа int (или nullptr, если marksCount == 0).

Любая операция, способная изменить состояние объекта (конструктор или сеттер),
ОБЯЗАНА восстанавливать инвариант. За это отвечает приватный метод `normalize()`.

--------------------------------------------------------------------------------
2.2. ПРАВИЛО ТРЁХ (THE RULE OF THREE)
--------------------------------------------------------------------------------
Фундаментальное правило C++ гласит:
«Если классу требуется явно реализовать хотя бы одну из следующих трех сущностей:
   1) Деструктор (~Groupmate)
   2) Конструктор копирования (Groupmate(const Groupmate&))
   3) Оператор присваивания копированием (operator=(const Groupmate&))
то ему почти наверняка необходимо явно реализовать ВСЕ ТРИ».

ПОЧЕМУ ЭТО ТАК:
Если вы не напишете конструктор копирования и оператор присваивания, компилятор C++
сгенерирует их автоматически. Сгенерированные компилятором версии выполняют
побитовое/почленное копирование (shallow copy / поверхностное копирование).

Что происходит при поверхностном копировании сырого указателя:
  Предположим, у нас есть объект A, у которого `marks` указывает на адрес памяти 0x1000.
  Мы выполняем:
      Groupmate B = A; // компилятор скопировал поля побитово!
  Теперь:
      A.marks == 0x1000;
      B.marks == 0x1000;
  Оба объекта ссылаются на ОДИН И ТОТ ЖЕ массив в куче!

  Последствия поверхностного копирования:
  1. Нарушение инкапсуляции: изменив оценку в объекте A, мы неявно изменим её в объекте B.
  2. CRASH / Undefined Behavior (Double Free): когда объект B выходит из области
     видимости, его деструктор выполняет `delete[] 0x1000`. Память возвращена ОС.
     Затем выходит из области видимости объект A, и его деструктор выполняет
     `delete[] 0x1000` ВТОРОЙ РАЗ! Повторное освобождение одной и той же памяти
     (double free) немедленно приводит к падению программы.
  3. Висячий указатель (Dangling Pointer): если один объект уничтожился раньше,
     второй остаётся с указателем на освобождённую память.

Решение: ГЛУБОКОЕ КОПИРОВАНИЕ (DEEP COPY).
Класс Groupmate сам запрашивает у операционной системы НОВЫЙ независимый блок
памяти через `new int[marksCount]` и поэлементно копирует туда значения оценок.
У каждого объекта свой личный участок памяти!

--------------------------------------------------------------------------------
2.3. РАЗНИЦА: КОНСТРУКТОР КОПИРОВАНИЯ VS ОПЕРАТОР ПРИСВАИВАНИЯ
--------------------------------------------------------------------------------
Это один из самых частых вопросов на экзаменах и собеседованиях.

+----------------------------+-------------------------------------------------+-------------------------------------------------+
| Критерий                   | Конструктор копирования                         | Оператор присваивания (operator=)               |
+----------------------------+-------------------------------------------------+-------------------------------------------------+
| Состояние целевого объекта | Объекта ЕЩЁ НЕ СУЩЕСТВУЕТ в памяти. Он только   | Объект УЖЕ СУЩЕСТВУЕТ и владеет ресурсами.      |
|                            | создается («рождается») из чистого листа.       | Его текущие ресурсы нужно сначала освободить!   |
+----------------------------+-------------------------------------------------+-------------------------------------------------+
| Освобождение старой памяти | НЕ ТРЕБУЕТСЯ, так как старой памяти не было.    | ОБЯЗАТЕЛЬНО ТРЕБУЕТСЯ (`delete[] marks;`),      |
|                            |                                                 | иначе будет утечка памяти (memory leak).        |
+----------------------------+-------------------------------------------------+-------------------------------------------------+
| Проверка самоприсваивания  | НЕ НУЖНА (нельзя инициализировать объект        | КРИТИЧЕСКИ ВАЖНА (`if (this == &other)`),       |
|                            | самим собой в момент его создания).             | иначе объект удалит свои собственные данные!    |
+----------------------------+-------------------------------------------------+-------------------------------------------------+
| Возвращаемое значение      | Нет (это конструктор).                          | Возвращает ссылку на текущий объект (`*this`),  |
|                            |                                                 | чтобы работала цепочка: `a = b = c;`            |
+----------------------------+-------------------------------------------------+-------------------------------------------------+
| Примеры синтаксиса         | Groupmate s2(s1);                               | s2 = s1;                                        |
|                            | Groupmate s3 = s1; // ВНИМАНИЕ: это ctor!       |                                                 |
|                            | void fn(Groupmate arg); // передача по значению |                                                 |
+----------------------------+-------------------------------------------------+-------------------------------------------------+

КЛЮЧЕВАЯ ЛОВУШКА ДЛЯ СТУДЕНТОВ:
Строка:
    Groupmate s3 = s1;
содержит символ `=`, но это НЕ оператор присваивания! Это КОНСТРУКТОР КОПИРОВАНИЯ
(так называемая копирующая инициализация, copy-initialization).
Правило простое: если в строке объявляется НОВАЯ переменная (слева указан тип),
то вызывается КОНСТРУКТОР.
Если переменная была создана РАНЕЕ на отдельной строке, а потом пишется `s3 = s1;`,
то это ОПЕРАТОР ПРИСВАИВАНИЯ.

3.2. ПРИВАТНЫЕ ПОЛЯ (СТРОКИ 7-12)
--------------------------------------------------------------------------------
  private:
      std::string firstName;  // Имя студента
      std::string lastName;   // Фамилия студента
      int age;                // Возраст студента (инвариант: [16, 100])
      int* marks;             // Указатель на динамический массив оценок в куче
      int marksCount;         // Количество оценок в массиве

Почему все эти поля объявлены в секции `private`:
  Это реализация принципа инкапсуляции. Если бы поля были `public`, любой внешний
  код мог бы написать:
      student.age = -500;
      student.marks = (int*)0xDEADBEEF;
  Объект был бы сломан, а программа бы упала. Скрывая поля в private, класс берет
  на себя монопольный контроль над их валидностью.

--------------------------------------------------------------------------------
3.3. МЕТОД НОРМАЛИЗАЦИИ normalize() (СТРОКИ 14-30)
--------------------------------------------------------------------------------
  void normalize() {
      auto capitalize = [](std::string& s) {
          if (!s.empty()) {
              s[0] = std::toupper(static_cast<unsigned char>(s[0]));
              for (size_t i = 1; i < s.size(); ++i)
                  s[i] = std::tolower(static_cast<unsigned char>(s[i]));
          }
      };
      capitalize(firstName);
      capitalize(lastName);
      if (age < 16) age = 16;
      if (age > 100) age = 100;
      for (int i = 0; i < marksCount; ++i) {
          if (marks[i] < 2) marks[i] = 2;
          if (marks[i] > 5) marks[i] = 5;
      }
  }

Разбор логики:
1. Лямбда-функция `capitalize`:
   - Принимает строку по неконстантной ссылке `std::string& s`, чтобы изменять её на месте.
   - Если строка пустая (`s.empty()`), ничего не делает (защита от падения при обращении к `s[0]`).
   - Первый символ `s[0]` переводит в верхний регистр (`std::toupper`).
   - Все остальные символы с индекса 1 до конца переводит в нижний регистр (`std::tolower`).

   ПОЧЕМУ ЗДЕСЬ НАПИСАНО `static_cast<unsigned char>`:
   Это очень тонкий момент стандарта C/C++!
   Функции `std::toupper` и `std::tolower` унаследованы из языка Си. Их сигнатура:
       int toupper(int ch);
   Стандарт строго требует: аргумент должен быть либо представим как `unsigned char`,
   либо равен `EOF` (-1).
   В большинстве компиляторов тип `char` является знаковым (`signed char`), то есть
   принимает значения от -128 до 127.
   Если в строке встретится символ с кодом > 127 (например, буква русского алфавита
   в кодировке Windows-1251 или спецсимвол), знаковый `char` превратится в отрицательный `int`!
   Передача отрицательного числа (не равного EOF) в `toupper` — это ОФИЦИАЛЬНОЕ
   НЕОПРЕДЕЛЕННОЕ ПОВЕДЕНИЕ (Undefined Behavior, крах программы или чтение чужой памяти таблицы).
   Приведение к `unsigned char` гарантирует, что число всегда неотрицательное [0, 255].

2. Ограничение возраста (Clamping):
   - Если `age < 16`, устанавливается 16.
   - Если `age > 100`, устанавливается 100.

3. Ограничение оценок:
   - Цикл по всем `marksCount` оценкам.
   - Если оценка `< 2`, подтягивается до 2.
   - Если оценка `> 5`, обрезается до 5.

3.4. КОНСТРУКТОР ПО УМОЛЧАНИЮ (СТРОКИ 33-35)
--------------------------------------------------------------------------------
  Groupmate() : firstName("Ivan"), lastName("Ivanov"), age(18), marksCount(0), marks(nullptr) {
      std::cout << "default constructor" << std::endl;
  }

Разбор логики:
- Вызывается при создании объекта без аргументов: `Groupmate student;`.
- Инициализирует поля безопасными дефолтными значениями:
  * Имя: "Ivan", Фамилия: "Ivanov", Возраст: 18.
  * Оценок нет: `marksCount = 0`, указатель `marks = nullptr`.
- Список инициализации (member initializer list): синтаксис `: field(val)` инициализирует
  поля ДО входа в тело конструктора, что быстрее и эффективнее, чем присваивание внутри `{}`.

--------------------------------------------------------------------------------
3.5. ИНИЦИАЛИЗИРУЮЩИЙ КОНСТРУКТОР (СТРОКИ 37-43)
--------------------------------------------------------------------------------
  Groupmate(const std::string& fn, const std::string& ln, int a, const int* m, int count)
      : firstName(fn), lastName(ln), age(a), marksCount(count) {
      marks = new int[marksCount];
      for (int i = 0; i < marksCount; ++i) marks[i] = m[i];
      normalize();
      std::cout << "initialization constructor" << std::endl;
  }

Разбор логики:
- Принимает пользовательские параметры: имя, фамилию, возраст, внешний массив оценок `m` и их количество `count`.
- Строки передаются по константной ссылке `const std::string&` — это исключает дорогостоящее
  копирование строкового буфера при вызове функции.
- В теле конструктора выделяется динамическая память в куче:
      marks = new int[marksCount];
- Циклом значения из внешнего массива `m` копируются в выделенный буфер `marks`.
- Вызывается `normalize()`, чтобы привести полученные данные к инварианту.
- Выводит сообщение: `"initialization constructor"`.

--------------------------------------------------------------------------------
3.6. КОНСТРУКТОР КОПИРОВАНИЯ (СТРОКИ 45-51)
--------------------------------------------------------------------------------
  Groupmate(const Groupmate& other)
      : firstName(other.firstName), lastName(other.lastName), age(other.age),
        marksCount(other.marksCount) {
      marks = new int[marksCount];
      for (int i = 0; i < marksCount; ++i) marks[i] = other.marks[i];
      std::cout << "copy constructor" << std::endl;
  }

Разбор логики:
- Вызывается, когда создается НОВЫЙ объект как клон существующего `other`:
      Groupmate s2 = s1;
      Groupmate s2(s1);
- Параметр `const Groupmate& other`: константная ссылка на копируемый объект.
  Константная — потому что мы не имеем права менять оригинал.
  Ссылка — потому что если бы мы передавали по значению, то для передачи аргумента
  пришлось бы вызвать... конструктор копирования! Это вызвало бы бесконечную рекурсию.
- Выделяет СОБСТВЕННЫЙ независимый блок памяти:
      marks = new int[marksCount];
- Поэлементно копирует оценки из `other.marks`.
- Внимание: вызывать `normalize()` здесь нет необходимости, так как объект-оригинал
  `other` уже гарантированно находится в нормализованном состоянии благодаря своему инварианту!
- Выводит сообщение: `"copy constructor"`.

--------------------------------------------------------------------------------
3.7. ОПЕРАТОР ПРИСВАИВАНИЯ (СТРОКИ 53-64)
--------------------------------------------------------------------------------
  Groupmate& operator=(const Groupmate& other) {
      std::cout << "assignment operator" << std::endl;
      if (this == &other) return *this;
      firstName = other.firstName;
      lastName = other.lastName;
      age = other.age;
      delete[] marks;
      marksCount = other.marksCount;
      marks = new int[marksCount];
      for (int i = 0; i < marksCount; ++i) marks[i] = other.marks[i];
      return *this;
  }

Разбор логики:
- Вызывается, когда УЖЕ СУЩЕСТВУЮЩЕМУ объекту присваивают значение другого существующего:
      s2 = s1;
- Возвращаемый тип `Groupmate&` и возврат `*this`:
  В C++ оператор присваивания традиционно возвращает ссылку на левый операнд.
  Это позволяет писать каскадные цепочки присваивания:
      s1 = s2 = s3; // Сначала s2 = s3, затем s1 = результат
- ШАГ 1: Защита от самоприсваивания (`if (this == &other) return *this;`):
  Указатель `this` содержит адрес текущего объекта. Ссылка `&other` — адрес источника.
  Если программист написал `s1 = s1;`, адреса совпадут.
  ЧТО СЛУЧИТСЯ БЕЗ ЭТОЙ ПРОВЕРКИ:
    Код пойдет дальше и выполнит `delete[] marks;`. То есть объект УДАЛИТ СВОЙ СОБСТВЕННЫЙ МАССИВ!
    Затем строка `marks[i] = other.marks[i];` попытается прочитать данные из `other.marks`,
    который указывает на ТОЛЬКО ЧТО УДАЛЕННУЮ ПАМЯТЬ! Это классический Use-After-Free
    и чтение мусора / падение.
- ШАГ 2: Копирование примитивных полей (`firstName`, `lastName`, `age`).
- ШАГ 3: Освобождение старой динамической памяти:
      delete[] marks;
  У текущего объекта уже был свой массив. Если не вызвать `delete[]`, а сразу
  написать `marks = new int[...]`, старый адрес потеряется навсегда — это УТЕЧКА ПАМЯТИ (Memory Leak).
- ШАГ 4: Выделение нового блока памяти под размер массива из `other` и копирование оценок.
- ШАГ 5: Возврат разыменованного указателя `*this`.

--------------------------------------------------------------------------------
3.8. ДЕСТРУКТОР (СТРОКИ 66-68)
--------------------------------------------------------------------------------
  ~Groupmate() {
      delete[] marks;
  }

Разбор логики:
- Автоматически вызывается при выходе объекта из области видимости (завершение блока `}`,
  выход из функции, уничтожение объемлющего объекта) или при вызове `delete ptr`.
- Освобождает память массива через `delete[] marks;`.
- Важно: если `marks == nullptr` (например, объект создан дефолтным конструктором),
  вызов `delete[] nullptr` по стандарту C++ абсолютно безопасен и ничего не делает.
- Почему `delete[]`, а не `delete`:
  В C++ память, выделенная через `new Type[N]`, обязана освобождаться через `delete[]`.
  Одиночный `delete` приведет к неопределенному поведению (UB).

6. ВОПРОСЫ ПРЕПОДАВАТЕЛЯ НА ЗАЩИТЕ И ОТВЕТЫ
================================================================================

В: Что такое «Правило трёх» (Rule of Three) и почему оно актуально для класса Groupmate?
О: Правило трёх гласит: если в классе объявлен деструктор, конструктор копирования
   или оператор присваивания, класс должен реализовывать все три.
   В классе Groupmate ресурсом является динамический массив `int* marks`. Если не
   написать конструктор копирования и оператор присваивания, компилятор сгенерирует
   поверхностное копирование: несколько объектов будут указывать на один и тот же
   массив в куче. При их уничтожении возникнет Double Free (двойное освобождение
   памяти), что приведет к аварийному завершению программы.

В: Зачем в операторе присваивания проверка `if (this == &other)`?
О: Это защита от самоприсваивания (`a = a`). Если её убрать, выполнение дойдет до
   строки `delete[] marks;`. Объект удалит свой собственный массив, а затем
   попытается скопировать данные из `other.marks` (который указывает на уже
   освобожденную память). Это приведет к чтению мусора или краху (Use-After-Free).

В: Чем отличается строка `Groupmate a = b;` от строки `a = b;`?
О: В строке `Groupmate a = b;` создается НОВЫЙ объект `a` — поэтому вызывается
   КОНСТРУКТОР КОПИРОВАНИЯ.
   В строке `a = b;` объект `a` уже существует и имеет собственные ресурсы — поэтому
   вызывается ОПЕРАТОР ПРИСВАИВАНИЯ (operator=), которому предварительно нужно
   освободить старую память `a.marks`.

В: Почему все геттеры помечены словом `const`?
О: Ключевое слово `const` в конце сигнатуры метода сообщает компилятору, что метод
   гарантированно не изменяет состояние объекта (поля класса). Это позволяет
   вызывать геттеры для константных объектов и константных ссылок (`const Groupmate&`).

В: Почему в деструкторе используется `delete[]`, а не обычный `delete`?
О: Потому что память выделялась оператором `new[]` для массива (`new int[marksCount]`).
   По стандарту C++, парными являются строго `new` с `delete` и `new[]` с `delete[]`.
   Использование обычного `delete` для массива является неопределенным поведением (UB).

В: Почему в лямбде нормализации написано `static_cast<unsigned char>`?
О: Функции `std::toupper` и `std::tolower` ожидают аргумент, значение которого
   представимо в `unsigned char` или равно `EOF`. Если тип `char` знаковый (от -128
   до 127) и содержит код > 127 (например, не-ASCII символ), неявное расширение до
   знакового `int` даст отрицательное число, что вызовет Undefined Behavior.
   Приведение к `unsigned char` исключает эту проблему.

В: Что такое инвариант класса?
О: Это набор логических правил и ограничений, которые всегда истинны для объекта
   (корректное имя с заглавной буквы, возраст от 16 до 100, оценки от 2 до 5).
   Класс гарантирует сохранение инварианта при конструировании и при вызове сеттеров.
